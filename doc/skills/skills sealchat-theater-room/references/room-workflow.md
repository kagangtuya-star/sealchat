# 从模组到房间：工作流

以《乐园》（`rooms/paradise/`）为完整实例。每一步给出"产物"，做完再进入下一步。

## Step 1 · 读模组，做"情报分级"

把模组内容分成三栏，**只有第一栏能进房间**：

| 公开（可上墙） | GM 专用（只进控制台的文案/按钮名） | 秘密（永不出现） |
| --- | --- | --- |
| 标题、类型、规制、人数、时限、秘宝名与公开描述、导入 HO 的【使命】、NPC 公开形象、特殊规则文本、场景表 | 阶段名（高潮、结局）、GM 场景位置、事件触发点 | 【秘密】、真实身份、解除条件、暗号、BOSS 数据 |

产物：一张三栏清单。之后每写一段文字都对照它。
> 《乐园》踩过的坑：夜景黑板上曾写了一句与暗号近似的台词，已删除。

## Step 2 · 提炼母题与素材

问四个问题：
1. 模组**发生在哪里、什么时候**？（清陵学园 · 文化祭前日 · 9 月 30 日黄昏）
2. 模组的**机制**是什么？（4 巡时限、每巡回到同一天、告白）
3. 真相的**象征**是什么？（月读 → 月，契兔 → 兔，时牢 → 时钟）
4. 这个世界里有哪些**媒介、材质、文书、器物**？（课表、文化祭海报、黑板、校内广播……）

尽量多列，不急着挑：这是下一步风格发散的原料。
产物：素材清单（地点 / 机制 / 象征 / 媒介与材质）。

## Step 3 · 风格立项（发散 → 收敛）与定色

按 `design-essence.md` 第 3 节：
1. 用五个生成源（世界内媒介、机制即版式、平面设计流派与工艺、材质与光、反差与错置）组合出**至少 3 个差异很大的方向**（稳妥 / 跳出 / 激进），每个写成概念卡：概念句、主窗、配色、字体、标志性叙事动效、对话框。
2. 用新意自检打分，**默认选最大胆且满足全部硬约束的方向**；方向分歧会显著影响全局时，先把概念卡给用户选。
3. 在选定方向里分配物件角色：主窗物件（乐园：黑板）、计数物件（日历 + 「正」字）、持续动效（赤蜻蜓 / 夕光尘埃 / 倒走的钟）、标志性叙事动效。
4. 定色：颜色要讲故事（乐园的红＝告白与血）。"1 底 + 1 线 + 1 点"是默认值，风格需要时可以打破（套色、单色、高饱和），并为高潮准备同构图的变体（变明度、变底色，或让版面"变质"）。

产物：选定方向的概念卡（附落选方向一句话说明）、母题表（见 `rooms/paradise/README.md` 第 1 节）、两组 CSS 变量。

## Step 4 · 规划小剧场场景与事件

| 模组阶段 | 舞台场景 | 入场动画 | GM 事件（同步特效） |
| --- | --- | --- | --- |
| 导入 | 序幕 | 挂载即播 | — |
| 主阶段 | 日景 | — | 场景横幅、计数、惨剧、谜团 |
| 高潮 | 夜景 | 破绽特效 | 变身 |
| 结局 | 任意 | — | 结局 A / B（常驻卡） |

原则：**大的氛围切换用小剧场场景，小的叙事节点用 Events**；结果状态写 Storage。

## Step 5 · 组件拆分

`templates/` 提供的是**工程骨架**（缩放、运行时、同步、角色切换、对话框规格、导出），视觉部分按 Step 3 选定的方向**重写**，不要被模板的主题 / 边框 / 母题参数限定。只有用户要求快速出图、或次要组件，才直接套参数。

| 需要 | 模板（取骨架） | 视觉上要做的 |
| --- | --- | --- |
| 开场 | `opening.html` | 按方向重写分镜：开场动作从媒介的物理行为里找（打印、开机、展开、复印、显影）；多段分镜参考 `rooms/paradise/01-opening.html` |
| 主背景 | `frame.html` | **默认手绘专属背景**（参考 `02-stage-day.html`）；版面结构跟随方向，不必是"中窗 + 两翼" |
| 菜单 / 表格 / HO | `dossier.html` | `DATA` 填内容；吊签、卡片、翻面的外观按方向改（卷宗夹、货架标签、频道旋钮……） |
| 持续动效 | `ambient.html` | 预设粒子够用时改 `CONFIG.preset`；方向需要时自写（胶片闪烁、霓虹不稳、墨迹渗出） |
| 叙事事件 | `stage-core.html` | 幕表、计数名、字卡；把标志性叙事动效写成专属 FX（参考 `04-timeloop.html`） |
| 对话框底图 | `dialogue-box.html` | 取画布规格与参考线；美术按房间的主窗 / 媒介手绘专属版（参考 `07-dialogue-box.html`），导出 PNG |

单个文件超过 ~70 KB 就该拆。

## Step 6 · 实现规范

- 1920×1080 设计画布 + `scale = max(W/1920, H/1080)` 覆盖缩放；主窗默认 960×540 @ (480,140)，方向需要时可改位置、尺寸与形状，并写进 README。
- 需要同步的组件：在 `<script>` 中放占位
  ```
  /* <sealstage-runtime> */
  /* </sealstage-runtime> */
  ```
  然后运行 `python3 scripts/sync_runtime.py <文件或目录>` 注入运行时。
- 叠加层 `html, body { background: transparent }`；加 `<meta name="color-scheme" content="light dark">`。
- 程序化美术优先：SVG 路径 / 渐变 / `feTurbulence` 纸纹 / canvas 粒子；用 seeded random 让每次加载构图一致。
- 文字用 Google Fonts（马善政 / 志莽行 / 站酷快乐 / 思源宋体）并提供系统字体回退；样式表必须**非阻塞**加载（`media="print" onload="this.media='all'"`），否则字体源不可达时整个组件会空白直到请求超时。
- `prefers-reduced-motion`：关位移、保淡入。
- 对 `.center { translate:-50% -50% }` 元素做动画时，关键帧必须保留这个 translate（用 `fadeupc` 一类变体），否则会跳位。
- SVG 内旋转：`transform-box: fill-box` 或明确 `transform-origin`（viewBox 原点不是中心）。
- 竖排 flex 容器：`writing-mode: vertical-rl` 下用 `flex-direction: column` 才是从右到左排列。

### 对话框底图

- 画布 = 对话框宽高比（默认 1920×336）；名字区 (48,22) 653×40、正文区 (48,94) 1824×228、右上角约 180×90 留给按钮。
- 名札深底（名字是角色色）；正文区低对比；装饰集中在上沿带与下沿，可出血到画布边缘。
- `python3 scripts/export_png.py <设计页> <out.png>` 导出并校验透明通道；规格与风格匹配表见 `dialogue-box.md`。

## Step 7 · 验证

1. `python3 scripts/check_embed.py <目录>`：体积、沙箱禁用 API、透明背景、color-scheme、运行时同步。
2. 写一个本地预览台（参考 `rooms/paradise/index.html`）：按场景挂载组件、模拟浮窗控制台，在浏览器里逐个触发事件。
3. 截图检查动画时，用 `document.getAnimations().forEach(a => { a.pause(); a.currentTime = T })` 定格到指定时刻，避免截图延迟。
4. 对话框：在舞台合成预览里叠到主舞台上看一遍（示例名字 + 两行正文），确认不抢戏、按钮区干净。
5. 再按 Step 1 的三栏清单通读一遍所有可见文字（包括对话框底图）。
6. 对照截图再做一次 `design-essence.md` 3.4 新意自检：成品是否还保有概念卡里的视觉发明，有没有在实现中退化回模板默认样子。

## Step 8 · 交付

- 每个组件一份 HTML（直接复制进 iForm「嵌入代码」）。
- 对话框底图 PNG（附设计源 HTML，方便以后改色或出夜版）。
- 一份 README：风格概念（概念句、选定理由、视觉发明）、文件清单、iForm 与 Embed API 设置、场景搭建表、主窗坐标、对话框设置、"模组进程 × GM 操作 × 玩家看到"对照表、自定义入口、注意事项。
