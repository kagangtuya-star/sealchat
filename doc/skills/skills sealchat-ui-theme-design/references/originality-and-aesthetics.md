# 原创性边界与审美标准

## 1. 为什么不能仿造

用户要的是“我们团的界面”。照搬参考主题或现有产品，会让主题失去和这个团的联系，也可能涉及他人的商标、美术与界面版权。参考主题是接口教材，不是视觉起点。

## 2. 不要复用的东西

### 2.1 仓库参考主题的标志性手法

这些已经属于参考主题的“签名”。新主题不要把它们作为核心母题，也不要换色后照用：

| 参考主题 | 不要复用的签名 |
| --- | --- |
| NEON//RUNNER | 透视网格地面 + 扫描线、切角面板、酸性黄/冰青/警报红三色、开机序列、频道标题故障切片与色散、顶栏 HUD 时钟/节点/计数 |
| R'LYEH ARCHIVE | 贴胶带的旧照片头像、索引卡频道 + 打孔、蜡封发送按钮、打字机纸卷输入区、雾气/触须/注视之眼、SAN 仪表、禁忌词蠕动、d100 印章 |
| TRIANGLE AGENCY | 员工手册白纸 + 黑细线 + 红三角、工牌 HUD、混沌计数、剧透涂黑条、内部备忘弹窗、现实偏移 |
| CHANNEL API LAB | Windows 97 浮窗与灰色立体按钮 |

也不要沿用它们的私有前缀（`--nr-*`、`--rl-*`、`--ta-*`、`.nr-*`、`.rl-*`、`.ta-*`、`sc-api-lab`）。`check_theme.mjs` 会对此报警。

如果用户的线索**真的**导向类似的物件（例如世界里确实有打字机），可以使用，但表现方式必须来自这个世界的具体细节，并且不能和参考主题的实现相似。交付时说明这一点。

### 2.2 外部作品与品牌

- 不复刻某个游戏、应用、网站或操作系统的界面布局、图标、Logo、官方插画、专有字体或商标视觉。
- 用户的世界基于商业 TRPG 或作品时，可以在说明里提作品名作为题材描述，但视觉上提炼题材的情绪与材料，不使用官方标志、封面美术或标志性版式。
- 用户点名“做成像 X 一样”时，问清楚他们喜欢 X 的哪一点，用这个团自己的材料重新表达，并说明原因。

### 2.3 泛滥的默认审美

这些不是禁止项，但出现时要问自己“线索在哪里”：

- 没有依据的紫蓝渐变、霓虹描边、玻璃拟态。
- 所有东西都加圆角 + 大阴影。
- 用 emoji 当装饰图标。
- 为了“有氛围”加粒子、光斑、持续闪烁。

## 3. 原创性自检

在阶段 2 选方向后、阶段 6 交付前各做一次：

- [ ] 隐喻来自这个世界内部的一件具体物品或场所，能说出它的出处。
- [ ] 签名元素在参考主题和常见产品里找不到同款。
- [ ] 每个装饰母题都能回指线索板上的某一条。
- [ ] 不包含外部品牌的 Logo、官方美术、标志性界面布局。
- [ ] 私有前缀、class 名、文案都是新写的，没有从参考主题复制。
- [ ] 换掉世界名后，这个主题放到别的团里会显得“不对劲”。如果放哪个团都合适，说明还不够定制。

## 4. 审美评分表

每项 0～2 分。总分低于 12，或任一项为 0，都要回去修改。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 概念一致 | 元素彼此无关 | 大体统一，有几处跑题 | 每处细节都在讲同一个隐喻 |
| 克制 | 装饰到处都是，正文受干扰 | 有少量多余装饰 | 1 个签名 + 2～3 个辅助母题，正文干净 |
| 层级 | 名字、时间、正文、按钮权重混乱 | 主次可辨但不够清晰 | 一眼能分清说话人、正文、操作 |
| 色彩 | 颜色没有逻辑或对比不足 | 有逻辑但比例失衡 | 主色、底色、强调色比例清楚（约 60/30/10），强调色有含义 |
| 字体 | 字体与概念无关或可读性差 | 合适但没有性格 | 字体性格与书写载体一致，中文 fallback 完整 |
| 日夜 | 只有一套成立 | 两套都可读但情境相同 | 两套是同一概念的两种情境，都完整 |
| 动效 | 无意义或持续干扰 | 有意义但偏多 | 少而准，表达世界里的“动”，可被减少动画关闭 |
| 细节 | 浮层、空状态、窄屏没处理 | 处理了一部分 | 浮层、空频道、焦点、滚动条、窄屏都照顾到 |
| 可用性 | 遮挡或隐藏了功能 | 有轻微的点击区域或对比问题 | 所有功能可用，焦点可见，对比达标 |

## 5. 几条具体的美观原则

- **正文是主角。** 正文区域背景要安静，纹理透明度低，行长和行距不被装饰挤压。
- **装饰住在边缘。** 边框、角落、标签、分隔线、背景远处，比正文中间更适合放装饰。
- **一处出彩。** 签名元素放在用户最常看的位置之一（激活频道、消息头、输入区、发送按钮），其余地方安静配合。
- **重复产生秩序。** 同一个形状或线型在不同组件中重复出现（例如同一种角标），比每个组件各自发明更高级。
- **材质要轻。** 纹理用低透明度的渐变或 SVG data URI，不要大面积高对比图案。
- **日夜分别调。** 夜间降低大面积底色的饱和度，强调色提亮；日间加深文字，避免浅灰字。
- **状态要明确。** 悬停、激活、焦点、禁用各不相同，不能只靠颜色区分。
- **窄屏不是缩小版。** 窄屏去掉装饰性阴影与大边距，保住正文宽度和输入区。
