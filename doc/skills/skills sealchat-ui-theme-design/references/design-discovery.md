# 线索收集与概念生成

这一份讲怎么从用户那里拿到“能用来设计的东西”，以及怎么把它们变成设计决定。

## 1. 什么算线索

形容词不是线索。“暗黑”“高级感”“赛博”只说明了用户想要的感觉，没有告诉你该画什么。线索是能落到画面上的具体东西：

| 线索类型 | 例子 | 能决定什么 |
| --- | --- | --- |
| 世界内的书写载体 | 航海日志、审讯记录、手抄经、出租车调度屏、学生会公告栏 | 消息区的材质、行线、头像框、输入区形态 |
| 世界内的物件与地点 | 煤油灯、钟楼、病历夹、霓虹招牌以外的东西：路牌、票根、印章 | 签名元素、纹理、按钮形态 |
| 光源与时间 | 烛光、日光灯、极夜、黄昏、潜水艇红灯 | 日夜两套配色的情境、暗角、阴影方向 |
| 社会结构 | 教会、公司、帮派、学院、船员 | 文案语气、编号格式、等级视觉、徽记形状 |
| 规则机制 | d100 成功等级、骰池、压力/疯狂/混沌值、卡牌、资源 | CSS 状态标记或 JS 机制钩子 |
| 团的习惯 | 紧凑布局、气泡布局、多手机、长文 RP、快节奏骰子 | 密度、字号层级、窄屏优先级、动效频率 |
| 禁忌与敏感 | 怕闪烁、色弱、不想要血腥、讨厌某种颜色 | 硬约束，优先级最高 |
| 已有素材 | 世界封面图、团徽、手绘地图、角色卡配色 | 色彩提取、形状母题（只取颜色和形状关系，不直接嵌图） |
| 世界数据 | 世界名、频道名、术语表、角色名 | 文案、标签、频道列表的隐喻 |

## 2. 问题库

一次最多问 3～6 个。先看用户已经说了什么，只问缺口。问题要具体，给出示例让用户容易回答。

**世界与故事**

- 用一两句话讲讲这个世界或这个团在玩什么？
- 角色们平时在什么东西上读写文字？（信、终端、卷轴、广播、手机、墙上的涂鸦……）
- 这个世界里最常见的一种光是什么？白天和深夜的差别是什么？
- 有没有一件物品、一个地点或一个符号，大家一看到就知道“是这个团”？

**气质与偏好**

- 跑团时希望界面带来什么情绪：紧张、安心、怀旧、荒诞、庄严？
- 有没有喜欢的参考（图片、电影画面、书的装帧）？我会提取感受，不会照搬。
- 有没有明确不要的：颜色、闪烁或动效、恐怖元素、过于花哨的装饰？

**规则与玩法**

- 用什么规则或骰制？骰子结果长什么样（可以贴一条真实的骰子消息）？
- 有没有希望界面“看见”的机制：成功等级、骰池计数、压力或疯狂值、回合、资源？
- 场内（IC）和场外（OOC）在你们团里差别大吗？希望它们看起来多不一样？

**使用环境与范围**

- 大家多用日间还是夜间、电脑还是手机？常用紧凑布局还是气泡布局？
- 这是平台包（整个站点）还是某个世界的包？平台有没有开启世界 JavaScript？
- 需要覆盖哪些页面：只有聊天，还是登录、世界大厅、世界控制台、OB 旁观、公开 LOG、嵌入页也要？

**追问技巧**

- 用户给出形容词时，追问“它让你想到什么具体的东西或场景”。
- 用户给出参考作品时，追问“你最喜欢它哪一点：颜色、质感、排版，还是某个细节”。
- 用户回答“都行”时，给两个具体选项让他选，而不是再问一个开放问题。

## 3. 线索板

把收集到的线索整理成表，至少 6 条。每条标来源，便于之后说明每个设计决定的依据。

| # | 线索 | 来源 | 可能的设计用途 |
| --- | --- | --- | --- |
| 1 | …… | 用户原话 / 附件 / 世界数据 / 推断 | …… |

标出 1～2 条**核心线索**：它们决定隐喻和签名元素。推断出来的线索要在交付时告诉用户。

## 4. 从线索到设计的转化

### 4.1 找隐喻

问自己：“如果 SealChat 是这个世界里的一件真实物品，它会是什么？”答案要满足：

- 世界内部存在，角色会接触到；
- 能承载“多人轮流说话 + 记录”的功能（聊天就是一种记录）；
- 有明确的材质、光线和书写方式。

隐喻决定整体：频道列表是这件物品的什么部分？消息是什么？输入区是什么？头像是什么？场外发言是什么？

### 4.2 拆成设计杠杆

| 杠杆 | 从隐喻中问什么 | 落在哪里 |
| --- | --- | --- |
| 材质 | 这件东西摸起来是什么？ | `body` 背景、`header`、`sidebar`、气泡背景 |
| 光 | 光从哪里来、什么颜色、多强？ | 暗角、阴影方向、日夜情境 |
| 线 | 物品上有哪些线：格线、缝线、电路、刻痕？ | 边框、分隔线、行线 |
| 字 | 这件物品上的字是怎么来的：手写、打字、印刷、雕刻、像素？ | `--sc-font-family`、名字/时间/标签字体 |
| 色 | 主色来自哪件实物？强调色代表什么含义？ | 私有令牌 → 语义变量 |
| 记号 | 这个世界怎么标记重要、危险、已读、秘密？ | 激活频道、关键词、悄悄话、剧透、骰子结果 |
| 声音（文案） | 这个世界的人怎么称呼“频道”“消息”“发送”？ | `content:` 标签、空频道提示、HUD |
| 节奏（动效） | 这个世界里什么东西会动？它慢还是快？ | 新消息到达、悬停、激活态；全部可被减少动画关闭 |

### 4.3 机制钩子

规则机制适合用很轻的方式被看见：

- 纯 CSS：利用已有状态（IC/OOC、悄悄话、激活频道、自己的消息）改变样式。
- 脚本标记：解析骰子结果，给消息行写 `data-<prefix>-*`，再由 CSS 呈现（印章、角标、边框颜色）。
- 本地 HUD：只在本浏览器保存的计数器或氛围值，明确告诉用户它不是游戏数据。
- 共享状态：只有确实需要多人同步时才用 `sc.channel()` 的 Storage / Events，并按最小权限声明能力。

机制钩子只在用户的规则里真实存在时才做，不要为了炫技发明机制。

### 4.4 发散 2～3 个方向

几个方向之间要在**隐喻层面**不同，而不只是换颜色。可以用这些轴拉开差异：

- 视角：角色手里的物件 / 机构的系统 / 环境本身（天空、海、墙）。
- 年代或技术层级：手工 / 机械 / 电子 / 超自然。
- 情绪：亲密 / 冷峻 / 荒诞 / 庄严。
- 密度：极简留白 / 信息密集的仪表 / 手工拼贴。

每个方向都写成阶段 2 要求的格式，并注明它主要依赖哪几条线索。

## 5. 一个转化过程示意

下面只演示“线索怎样推出设计决定”的思路，具体结果不应复用。

> 线索：团在跑一个高原驿站的长线战役（用户原话）；角色常给远方写信（用户原话）；最常见的光是酥油灯（追问所得）；用 d20，关注大成功（骰子样例）；大家多用手机夜间（用户原话）。
>
> 隐喻：驿站的信件分拣台。频道是分拣格，消息是信笺，输入区是待封的信封，OOC 是写在信封背面的附言。
>
> 推出：暖色低亮度的夜间配色（酥油灯），纸张纹理只放在气泡底色和侧栏；频道激活态像信插进格子；名字用较窄的衬线体；大成功时脚本给消息行写 `data-xx-roll="crit"`，CSS 盖一枚邮戳式标记；窄屏优先保证信笺正文宽度，分拣格在窄屏下改成一行横向标签。

注意这个示意里每个决定都能回指到一条线索，这就是要求的密度。
