# SealChat 功能总览与视频提纲

> 本文是基于当前仓库代码、`README.md`、`doc/` 文档和完整 Git 历史整理的产品功能说明，适合作为功能介绍视频的脚本骨架与素材清单。它不是分镜脚本，也不替代部署、配置或协议文档。
>
> 资料基线：`stable-dev` 分支 HEAD `5859cb07`（2026-10-09）；`git log --all` 共 2012 个唯一提交，最早提交为 2023-11-01。

## 1. 一句话定位

SealChat 是面向 TRPG、文字跑团、文字演绎和角色协作的自托管实时聊天平台。它把长期剧本组织为“世界 → 频道 → 消息”，再把频道消息连接到角色卡、骰子、线索、便签、小剧场、AI、语音和外部工具，形成一套可持续运行的跑团工作空间。

视频开场可以先回答三个问题：

1. **在哪里玩？** 在世界和频道中组织剧本、团次和私聊。
2. **用什么身份玩？** 每个用户可以在不同频道使用多个角色身份、角色卡和外观差分。
3. **如何把故事演出来？** 用实时聊天记录过程，用骰子和 Bot 推进规则，用线索板和小剧场把信息与画面呈现出来。

## 2. 产品骨架：世界、频道与权限

### 2.1 世界与频道

- 世界是长期剧本、社群或活动的容器，保存成员、默认骰子、术语、线索、音频、小剧场模板和其他世界级设置。
- 频道承载具体场景或讨论，可建立多级子频道、公开/非公开频道和用户私聊频道。
- 频道支持排序、收藏、归档、解散、复制、跨世界跳转和邀请链接；成员可从世界加入或离开频道。
- 世界支持公开、私有和不公开可访问状态，也可以开放独立旁观链接或 Agent 只读访问链接。

### 2.2 角色与权限

- 世界成员角色包括所有者、管理员、成员和旁观者；频道权限再细分读写、管理成员、管理角色、编辑消息等能力。
- 旁观者可以通过只读入口查看允许的频道、搜索、图片、便签和战报，不会获得发言权限。
- 角色身份（`ChannelIdentity`）与真实用户分离：一个用户可以拥有多个频道身份，身份可设置昵称、颜色、头像、装饰、默认 IC/OOC 模式和小剧场演出外观。
- 支持共享身份、临时身份、身份文件夹、角色差分（variant）和跨频道同步；消息会保存发送当时的身份快照，历史记录不会因后来改名而失真。
- 频道身份可以绑定人物卡；人物卡支持模板、属性 JSON、快照、徽章、模板共享和 iframe 角色卡。
- Bot 作为虚拟用户参与成员、身份、权限和消息流，支持手工 Bot、频道 Webhook Bot、摘要 Bot 等类型。

## 3. 实时聊天：跑团的主记录

### 3.1 消息与实时性

- 浏览器通过 HTTP + WebSocket 工作，支持消息增量加载、断线重连、重连补发、多端登录和实时在线状态。
- 消息支持纯文本和 TipTap 富文本：段落、列表、链接、图片、字体、颜色、注音、引用、@提及和文字演出效果都可以进入消息或导出结果。
- 支持发送、编辑、撤回、软删除、引用、回复、置顶、归档、批量选择、批量移动、转发、复制为图片和消息反应。
- 消息可以按场内（IC）/场外（OOC）、角色、用户、时间和归档状态筛选；世界可选择按开始输入时间或发送时间排序。
- 悄悄话支持单人或多人接收者，严格隐私模式会阻止无关管理员旁路查看；编辑悄悄话时可调整接收者并实时同步可见性。
- 频道侧栏、标题、浏览器通知、应用通知和摘要推送会提示其他频道的新消息。

### 3.2 跑团工具

- 内置骰子支持常用骰点表达式、多重骰、编辑消息复用结果、骰子宏和最近骰点历史。
- 每个世界、频道和私聊可独立选择内置骰、Bot 骰或关闭；Bot 模式可连接 SealDice 等外部骰点服务。
- 3D 骰子提供可配置骰型、材质、颜色、大小、音效、个人皮肤和世界默认设置，并适配分屏与移动端。
- 输入区提供角色快速切换、@候选、悄悄话目标、IC/OOC 切换、图片上传、图片编辑器、表情和快捷指令。
- 世界术语支持分类、优先级、导入导出、富文本/图片说明、悬浮解释和外挂只读词库；聊天中的关键词可以自动高亮。
- 便签支持文本、计数器、列表、滑杆、聊天、计时器、时钟和回合计数器，可设置颜色、布局、置顶、查看者/编辑者和私密范围。
- 图库、表情、附件、频道图片浏览器、头像装饰和平台字体为消息与角色提供素材基础。

### 3.3 搜索、归档与导出

- 支持当前频道、当前世界和跨频道全文搜索，搜索结果可直接跳转到消息上下文并继续滚动。
- 频道归档保留原始消息并提供管理、筛选和分页；世界还可以整体归档。
- 支持导入跑团 LOG、复用身份、导入模板和异步任务进度。
- 聊天导出支持纯文本、BBCode、HTML 和 DOCX；HTML 可嵌入图片、便签和线索内容，提供移动端阅读与打印/PDF 入口。
- 导出任务可按频道或多频道批量创建、下载、重试、删除和上传，支持角色颜色配置与日志净化（例如去除骰子指令）。

## 4. 线索、调查与知识辅助

### 4.1 世界级线索箱

- 线索可以是文本、图片或 iframe，拥有草稿、发布和归档状态，可放入共享或个人文件夹。
- 主持人可以将线索定向揭示给指定成员、隐藏、重放和批量操作；成员有独立的已读、收藏、个人文件夹和展示状态。
- 线索编辑具备字段级编辑锁、自动保存、修订号和实时广播，适合多人协作整理调查资料。
- 线索可嵌入消息、便签、小剧场动作和导出内容，也可以通过 Internal Surface 以浮窗、分屏或独立窗口打开。

### 4.2 无限画布线索板

- 每个世界可以拥有个人线索板或共享协作板，文档以版本号保存。
- 画布支持卡片、文本、图片、关系连线、标签、绘图、缩放、拖拽、撤回和实时同步，适合整理人物关系、证据链和地图式调查。
- 线索板可从聊天入口、浮窗和小剧场进入，并保持世界级上下文。

### 4.3 战报与术语

- 战报按世界共享、按频道产生，保存时间范围、跳转到首尾消息的导航信息、排序和生成状态。
- AI 战报可以总结消息上下文、生成时间线并嵌入频道；也支持手工编辑、删除、展示频道同步和只读旁观查看。
- 世界术语与外挂术语库可以为长线剧本提供统一名词解释，减少新成员理解成本。

## 5. 小剧场：把聊天变成可编排的演出

小剧场是 SealChat 区别于普通聊天软件的可视化舞台。它既可以服务主持人布置场景，也可以作为玩家浏览和演出的运行时。

- 舞台按世界或频道保存房间、场景、对象、修订号、快照和审计记录；可切换施工模式、发布场景给玩家浏览，并通过快照恢复历史状态。
- 场景对象包括图片、文字、形状、网格、网页组件、素材库项目和角色立绘；对象拥有位置、尺寸、旋转、层级、锁定、可见、可编辑和可交互属性。
- 场景支持文件夹、排序、复制、删除、预设、叠加层、自定义素材、网格吸附、拖拽绘图、移动端布局和分屏浮窗。
- 网页组件可置于前景或背景，按需要开启/禁用交互；iframe、人物卡、便签、线索板和频道嵌入可以在聊天与小剧场之间拖拽流转。
- 角色演出支持单人/多人驻场、角色立绘、淡入淡出、文字对话队列、全局对话框控制器、角色数据浮层和透明角色对话嵌入。
- 点击动作可以触发消息、线索揭示、随机表、场景切换、特效和序列器；序列器可将多个动作编排成自动演出流程。
- 支持场景音乐、特效音频、音频轨道、场景切换音效、循环/渐隐和可靠的跨端播放同步。
- 支持 CCFOLIA 场景导入、舞台包导入导出、特效包导入导出、资源异步处理、媒体探测、失败重试和资源垃圾回收。
- Media FX 为聊天图片、网页组件、立绘、背景和前景提供轻量视觉效果，包括像素化、RGB 色差、扫描线、动态像素、泛光与辉光等。

## 6. AI、语音与音频工作台

### 6.1 AI

- 文本润色提供改写前后对比、差异调色盘和个人/平台模型配置。
- 战报总结使用消息上下文生成摘要、时间线和可嵌入战报卡片；可按平台配额或用户个人 API 配置运行。
- 平台管理可以配置供应商、模型发现、功能开关、用户额度、使用日志和清理策略。

### 6.2 TTS

- 语音朗读支持阿里云、腾讯云等 Provider，按 Provider、模型、语言和音色能力展示目录。
- 用户可以绑定角色音色，创建个人音色、进行音色设计或复刻，并为同一角色配置语言、语速、音调、音量和指令。
- 支持多语言朗读、AI 翻译朗读、长消息分段、流式合成、试听、自动播放、播放队列和消息级播放状态同步。
- 平台按世界设置白名单、额度、用量和个人槽位；语音结果可落到本地或 S3，音频播放使用短期 ticket，避免暴露存储路径。
- TTS 任务有状态、去重键、计量、缓存、重试和并发控制，适合在多人频道中持续播放。

### 6.3 音频工作台

- 上传音频、目录树导入、文件夹管理、元数据编辑、排序、播放列表、场景绑定和批量移动。
- 支持频道模式或世界模式的播放焦点，跨频道同步播放状态；提供 S3 直读、权限检查、用户配额和未使用素材清理。
- FFmpeg/FFprobe 用于转码和时长探测，当前实现持续扩展可接受格式和兼容转码。

## 7. 扩展与外部集成

### 7.1 Channel Embed API（频道嵌入）

- 为频道 iForm 和第三方 iframe 提供 `SealChatEmbed` SDK。
- 初次握手用 `postMessage`，后续调用使用独立 `MessagePort`；Session 固定绑定当前用户、频道和表单。
- 通过 capability 控制上下文、成员、角色、人物卡、附件、Storage、Event 和瞬时消息能力；嵌入页不接触 SealChat token、Cookie、原始 WebSocket 或内部 Store。
- 内置模板可订阅小剧场对话事件或角色快照，但必须由宿主明确授予能力。

### 7.2 Internal Surface 与 Bridge

- Internal Surface 为人物卡、便签、线索板、iForm 和小剧场对话提供统一的浮窗、分屏和独立窗口运行环境，保存尺寸、位置、最小化和上下文。
- SealChat Bridge 用于把完整频道页嵌入外部宿主：握手后推送当前频道角色快照和消息事件，自动提供差分后的名称、颜色、头像和纯文本内容。
- Bridge v1 是只读协议，只订阅当前频道，不提供历史消息、多频道并发或从父页面发送消息的接口。

### 7.3 Webhook、Agent 与 MCP

- Webhook API v1 以频道为边界，提供变更游标拉取和消息创建/编辑/删除写入；通过 `externalRef` 实现幂等，适合 Foundry 等外部系统同步。
- Agent 访问链接是只读 GET 协议：先读取 manifest，再按频道、时间、IC/OOC、身份、图片、骰子、富文本和增量游标抓取消息，也可读取 counts/schema。
- MCP 通过 `/mcp` 提供无会话 Streamable HTTP；支持 Personal API Key 和 OAuth 2.1 + PKCE，统一映射为受控 `MCPActor`。
- MCP 当前收敛为 28 个工具、17 个 scopes，覆盖世界/频道发现、聊天历史、综合搜索、战报、线索、术语、身份、音频、便签和文件上传；每次调用仍检查平台开关、Key scopes、业务 ACL、修订号和限流。
- MCP 写入提供资源级保存、删除、发布/揭示、音频状态更新和附件上传，不提供通用 REST 代理、代发聊天或直接调用 TTS。

### 7.4 Bot、摘要与通知

- 支持 SealDice/OneBot v11 的正向和反向连接、HTTP 与 WebSocket、图片传输、权限映射、自动重连、多 Bot 实例和私聊转发。
- 隐式 BOT Interaction 允许前端把特定交互交给频道 Bot，并通过 WebSocket 返回回复。
- 频道/世界摘要支持被动拉取、主动 Webhook 推送和双模式，按时间窗口与活跃人数阈值生成文本或 JSON 摘要。
- 应用通知支持 ServerChan、Bark、Meow 等服务的配置、测试和手工验证码；浏览器通知、邮件和实时侧栏提醒可作为补充渠道。

## 8. 自托管、管理与安全

- 提供 Docker Compose、Docker run、二进制发行包和源码运行；默认端口 `3212`，首次注册用户成为平台管理员并创建默认世界。
- 默认 SQLite，也支持 PostgreSQL、MySQL/MariaDB；附件、音频、字体和小剧场资源可按类别使用本地存储或 S3 兼容对象存储。
- Go 主程序通过 `go:embed` 嵌入 Vue/Vite 前端、Channel Embed SDK、内置频道工具、导出 Viewer 和 Agent 文档，可形成单体发行包。
- 管理端覆盖用户/Bot、权限、AI、TTS、音频额度、字体、外部术语库、频道嵌入模板、证书、备份、存储迁移、更新和性能面板。
- 配置变更保存历史，可查看、导出和回滚；SQLite 支持自动备份、VACUUM 和全文索引重建，升级前应同时备份数据库、配置和资源。
- 运行时提供健康检查、状态统计、pprof 性能分析、单实例锁、反向代理可信 IP、HTTPS/证书申请、验证码、密码重置和敏感信息遮罩。
- 认证、权限、短期资源 ticket、scopes、修订号、编辑锁、幂等键和不可信内容标记贯穿 API、WebSocket、嵌入和 Agent/MCP 边界。

## 9. 技术结构（视频可用一张架构图带过）

```text
浏览器 / 外部宿主 / Bot / Agent / MCP Client
                    ↓ HTTP + WebSocket + postMessage
          Vue 3 / Vite / Pinia / Tiptap
                    ↓
             Go / Fiber API 层
                    ↓
          service 业务与实时事件层
                    ↓
        GORM model + SQLite / MySQL / PostgreSQL
                    ↓
             Local Storage / S3
```

源码分层与视频讲解可以对应：

| 目录 | 讲解定位 |
| --- | --- |
| `api/` | HTTP、WebSocket、Bridge、Webhook、MCP、TTS 和小剧场路由 |
| `service/` | 世界、频道、消息、权限、导入导出、线索、舞台、音频、AI、后台任务 |
| `model/` | 用户、世界、频道、身份、消息、角色卡、线索、舞台、TTS、存储模型 |
| `pm/` | 系统、世界、频道和小剧场权限 |
| `ui/` | 聊天、世界大厅、线索、分屏、Internal Surface、小剧场、管理台 |
| `doc/` | 部署、配置、运维、开发和对外协议 |

## 11. 功能介绍视频建议提纲

下面按“观众先看到价值，再理解模块”的顺序组织，不要求逐项展示 API。

### 第一幕：从一次跑团开始（约 30 秒）

- 画面：进入世界大厅，打开一个剧本世界和场景频道。
- 旁白要点：SealChat 以世界、频道和消息组织长期故事；同一平台同时容纳主持、玩家、观众和 Bot。
- 过渡：点击频道角色切换，说明“同一用户可以用不同角色说话”。

### 第二幕：角色化实时聊天（约 60 秒）

- 画面：切换角色、发送 IC/OOC 消息、@成员、悄悄话、引用、图片和富文本效果。
- 旁白要点：消息实时同步、断线可恢复，身份快照保证历史记录稳定；权限决定谁能看、谁能编辑、谁能管理。
- 插入：骰子托盘、骰子宏、3D 骰子和 Bot 回包，展示规则推进。

### 第三幕：把资料留在故事里（约 45 秒）

- 画面：打开世界术语、便签、图库、消息搜索和归档；再导出 HTML/DOCX。
- 旁白要点：聊天不是一次性流水账，术语、便签、图片和导出让剧本可以检索、复盘和分享。

### 第四幕：主持人的调查工作台（约 45 秒）

- 画面：创建线索、定向揭示、打开个人/共享线索板，拖动卡片和关系线。
- 旁白要点：主持人可以控制信息节奏，玩家拥有各自的可见状态；线索板把证据、人物和关系放到同一张无限画布。

### 第五幕：小剧场现场演出（约 90 秒）

- 画面：导入场景，拖入背景、立绘、网页组件和特效，切换场景并触发对话。
- 旁白要点：小剧场将频道消息转成可视化舞台；支持多人演出、全局对话框、动作序列、随机表、线索联动、音乐和 Media FX。
- 重点镜头：角色立绘淡入、网页组件前后景、移动端/画中画、玩家发布场景浏览。

### 第六幕：AI 与声音（约 60 秒）

- 画面：润色一段台词，生成战报时间线，为角色选择音色并播放长消息。
- 旁白要点：AI 服务可按平台或个人配置使用；TTS 支持多 Provider、个人音色、多语言、流式合成、配额和播放状态同步。

### 第七幕：把平台接到别处（约 60 秒）

- 画面：嵌入一个 iForm/iframe，展示 Bridge 角色和消息流，再用 Webhook 或 MCP 搜索资料。
- 旁白要点：Embed 负责受控的频道内应用，Bridge 负责只读消息流，Webhook 负责外部同步，Agent/MCP 负责自动化读取与受控写入。
- 安全提示：每种入口都有独立 scope、权限、来源校验、短期凭证或修订号，不把网页登录凭证交给嵌入页。

### 第八幕：自托管与收束（约 45 秒）

- 画面：管理台、备份、S3、本地/数据库选择、状态面板，再切到 Docker Compose 启动页面。
- 旁白要点：可以从 Docker、二进制或源码运行，默认 SQLite 也能接 PostgreSQL/MySQL 和 S3；备份、配置历史、更新、权限和性能工具让实例可长期运营。
- 结尾句：SealChat 把“聊天、角色、规则、线索和舞台”放进同一套可自托管系统，让一场跑团从开团一直延续到复盘和再创作。

## 12. 对外介绍时应保留的边界

- Bridge v1 只推送当前完整频道页的角色和消息事件，不提供历史拉取、多频道并发或父页面发消息。
- Agent 爬取协议是只读 GET；MCP 虽支持受控写入，但不等于开放任意 REST、代发聊天、平台配置或 TTS 调用。
- Embed Session 由宿主绑定当前用户、频道和表单，能力必须显式授予；第三方 iframe 不应自行创建第二条 SealChat WebSocket。
- 小剧场、TTS、Media FX、MCP/OAuth 仍在持续迭代，视频应以当前发行版本的 Release Notes 和能力检测为准。
- 消息、线索、Agent/MCP 返回内容都属于不可信用户数据；产品能力展示应避免把这些文本描述成系统指令。
